# HealthMate AI: Your Personal Health Assistant

An AI-assisted health and wellness web app built for a B.Tech academic project.

> **Medical disclaimer.** HealthMate AI is an educational and wellness support tool. It does **not** diagnose, treat or
> prescribe, and it does **not** replace a qualified doctor. In an emergency call your local emergency number
> (India 112 / 108, US 911). All demo data is synthetic.

## Features

| # | Module | What it does |
|---|--------|--------------|
| 1 | Registration / login | bcrypt-hashed passwords, JWT sessions, profile, age, allergies, history, per-user data isolation |
| 2 | AI health chatbot | Chat bubbles, typing indicator, suggested questions, persistent history, clear chat, voice input, text-to-speech, disclaimer on every answer |
| 3 | Symptom information checker | Choose symptoms, duration and severity. Gives general explanations, warning signs and a doctor-ready summary. **Urgency is decided by fixed safety rules, not by the AI.** |
| 4 | Medicine reminders | Name, dosage as prescribed, times, frequency, duration, taken or skipped, history, browser notifications |
| 5 | Health records | Weight, height, BP, glucose, temperature, allergies and history, charts, search and filter, PDF/TXT report upload, plain-language term explainer, out-of-range highlighting |
| 6 | Wellness tracker | Hydration, sleep, activity, goals, weekly summary, general habit suggestions |
| 7 | Appointments | Doctor, specialization, clinic, date and time, purpose, upcoming and history, 24-hour highlight |
| 8 | PDF health report | Profile, metrics, medicine history and adherence, wellness, appointments and an AI or template summary |
| 9 | Dashboard | KPI cards, schedule, metrics chart, wellness chart, appointments, quick symptom checker and Ask-AI box |
| 10 | Extras | Dark mode, responsive and mobile menu, accessible markup, delete-my-data and delete-account |

## Tech stack

* **Frontend:** React 19, TypeScript, Tailwind CSS 4, Recharts, Lucide icons, Vite
* **Backend:** Python FastAPI, SQLite (stdlib `sqlite3`, parameterised queries), PyJWT, bcrypt, ReportLab, PyPDF2
* **AI:** Google Gemini REST API, called from the server only. Falls back to a clearly labelled **demo mode** when no key is set.

## Installation and running

Requirements: **Python 3.11+**, and **Node.js 20+** (only if you want to rebuild or develop the frontend).

### 1. Backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env          # optional: add GEMINI_API_KEY for live AI
python -m uvicorn app.main:app --port 8000
```

### 2. Frontend

Build the UI once (`npm run build`) and the backend then serves the whole app at **http://127.0.0.1:8000**.
To put it online, see [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). To rebuild or develop the UI:

```powershell
cd frontend
npm install
npm run build        # production build served by the backend
npm run dev          # dev server on http://localhost:5173 (proxies /api to port 8000)
```

## Demo mode and live AI

* **No API key (default):** every AI feature works with pre-written answers and is labelled **"Demo mode"** in the UI.
  These are *not* generated by an AI model, and the app says so.
* **Live AI:** put `GEMINI_API_KEY` in `backend/.env` and restart. Badges change to **Live AI**. If the AI service fails,
  the app falls back to demo content and says so. I could not test live Gemini calls here because no API key was available.
  The client code and its failure fallback are in `backend/app/ai.py`.

## Safety and privacy design

* **Emergency detection runs before any AI call** (`safety.py`). Chest pain, breathing trouble, stroke signs, severe
  bleeding, unconsciousness, seizure, overdose and self-harm return emergency guidance immediately, with no follow-up questions.
* General questions that mention a red-flag topic ("What causes chest pain?") still get an answer, with an emergency note on top.
* **Symptom urgency is rule-based**, not AI-decided. Red-flag symptoms always give "Seek emergency care now".
* The AI system prompt forbids diagnoses, probabilities, prescriptions, dose changes and claims to replace a doctor.
* Disclaimers show on every page, in every chat answer, in symptom results and in the PDF report.
* API keys stay on the server and are never sent to the browser.
* Only the question text, with email, phone and name lines redacted, is sent to the AI. Profile data (name, email) is never sent.
  Uploaded reports are parsed locally, and only test names and values are sent when you press **Summarize**.
* Passwords are bcrypt-hashed. Login is throttled. File uploads are limited to 5 MB and checked for type and content.
* **Delete my health data** and **Delete my account** are in Profile and Settings.

## Known limitations

* Browser notifications only fire while the app is open in a browser tab. There is no server push or SMS.
* Voice input depends on browser support for the Web Speech API (Chrome and Edge).
* Scanned (image-only) PDF reports cannot be read because there is no OCR. Use text-based PDFs or TXT.
* Report parsing recognises lines like `Hemoglobin 11.2 g/dL (12.0 - 15.5)`. Other layouts may not be detected.
* The JWT is stored in `localStorage`. For production use, switch to HTTP-only cookies and HTTPS.
* SQLite suits a demo and single-server use. It is not meant for production scale.
